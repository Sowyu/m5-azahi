# Offline daily-driver work, 2026-09-28

No connection to the laptop was available. The last hardware observations
remain those of 2026-09-13: one CPU online, failed USB networking and remote
access, intermittent trackpad startup, software rendering and unsafe sleep.
No hardware fix is claimed by this report. Source changes below are collected
on the `audit-2026-09-25` branch in
[PR #5](https://github.com/Sowyu/m5-azahi/pull/5). Build artifacts, firmware,
device captures and private research inputs remain on the home server.

## Changes checked on the home server

- USB startup now continues when a tether-specific optional network driver
  is unavailable. Required host drivers still stop startup on failure. A
  stage-specific error message preserves the first failure without unloading
  live modules. Ten mocked startup tests pass.
- Daily settings parse only DNF's global `[main]` exclusions, preserve repository
  sections and multiline lists, and reject configurations that disable the
  intended protection. Backups use unique names, even within one second.
  Fixture roots now apply to systemctl too. Fourteen tests pass after the
  inherited-configuration and quoting follow-up below.
- A read-only health report identifies missing USB controllers, phone functions,
  network interfaces, IPv4 addresses and default routes without printing
  identifiers or accessing MMIO. An address and route must belong to the same
  interface, with a usable default route. It also reports USB service state
  and the system's NTP synchronization flag. Nine synthetic-state tests pass.
  It refuses this non-J714s host.
  USB LPM output now names the allowed policy explicitly; this is not an L1
  activity report. The USB test plan preserves existing quirks and accounts
  for the kernel's XOR handling of dynamic flags.
- Standalone boot guards match complete, unique argument tokens. `maxcpus=18`,
  duplicate overrides and arguments after `--` cannot impersonate the required
  one-core boot limit. CPU probes also ignore init arguments after `--`.
  Eight loader tests and seven dependent SMP tests pass.
- The PCIe experiment formerly accepted partial or duplicate mode arguments.
  It now accepts one exact `probe` or `bringup` token before `--`, checks
  T6050/board 8/J714s identity, and refuses malformed requests before MMIO.
  The loader tests cover those refusals and ensure probe mode makes no writes.
  Bring-up requires both overlay nodes before MMIO, propagates tunable
  errors, and stops kernel handoff on failure. The earlier caller ignored
  failures. Preflight now checks translated controller and PMGR register
  ranges and the complete local tunable arrays before MMIO or power enable.
  Invalid widths, alignment, offsets and partial entries are refused before
  an earlier valid entry can write. Missing tunable properties remain optional.
  CPU, PCIe and kboot objects cross-compile with `-Werror` after
  these changes. That compile also caught a signed memory-region error
  stored in `size_t` in SEP setup; the check now uses the signed result directly.

These tests exercise host logic. They do not establish CPU startup, USB
electrical behavior, reliable input or safe power transitions.

The standalone source had an unresolved private PMGR lookup dependency.
A pinned patch now supplies the read-only die-0 lookup through the existing
m1n1 address resolver. Three sanitizer-backed groups test both table layouts,
all byte-valued indices, ambiguity and malformed input without MMIO. The
expanded offline builder compiles four loader objects with `-Werror`, and a
relocatable link resolves their custom references. It remains a component
build, with no complete boot image or new CPU entry result.

The offline iBootData decoder now consumes all four power-table sections of
the matching Stage2 release. Three synthetic format/bounds tests pass. Static
tracing identifies restoration records for all 18 RVBAR registers, plus two
conditional CPU_START-bank writes. The RVBAR handler reads existing values
and queues them for restoration. This supplies no new reset-release fix.
Offsets and reproduction commands are in the [SMP investigation](audit-2026-09-25/smp.md).

Input follow-up: the DockChannel source no longer includes a private build
path just for Apple's vendor ID. The exact-kernel Linux build also covers
this module with `--with-input`. It exposed two possible-uninitialized
warnings at firmware startup. Requiring the firmware lookup's documented
zero success return removes them; this is not evidence that the warnings
explain the intermittent AFE failure. Six host test groups pass, including
firmware-error containment under ASan/UBSan. Export and vermagic checks pass.

A second input finding concerns the common TX FIFO. Commands from different
HID interfaces held separate mutexes, while the underlying DockChannel sender
has no serialization. Their packet fragments could interleave. A shared
packet-level mutex now covers header, body, padding and checksum, and releases
before the ACK wait. A forced two-thread overlap passes with the lock and
reproduces checksum corruption with the lock removed. The test also checks
all four send-error exits release it. The updated input candidate rebuilt
against the exact devel RPM, and all seven build checks pass. No claim is made
that this explains the hardware's AFE boot failure.

GPIO event handling also checks both pulse-write return values before
acknowledging success. The old handler discarded errors from the pinned
kernel's integer-returning GPIO API. It keeps both pulse edges, including
release after an assertion error, and the default 10 ms delay. Invalid IDs
and unsupported operations now fail before GPIO acquisition. The sixth host
group checks success, either/both edge failures, exact ACK payloads and
refusals. Later kernelcache inspection found that Apple's resource action 3
uses `IOSleep(50)` between its two writes. A J714s-only `gpio_pulse_50ms`
option prepares that comparison; it defaults off. Tests cover both model and
option guards. No reset timing has been tested on the laptop.

The raw HID SET_REPORT path also now preserves the requested report type.
Feature writes had used output flags; the seventh host group reproduces that
mismatch and checks the corrected mapping, buffers and errno propagation.
Apple's SCM FIFO implementation independently confirms the two flags. The
MTP trackpad skips magicmouse's separate multitouch-enable command, so this
does not explain its AFE failure. The new candidate and all seven exact-kernel
build checks pass. Function addresses are in the kernel audit.

The storage timeout review confirmed an earlier open risk more precisely:
an admin request can retain the only usable admin tag while its timeout path
synchronously tries to allocate another tag to delete the I/O queue. This can
stall before reset work or disk removal. The kernel audit now names that
cycle and corrects the earlier claim that timeout always reaches removal.
No recovery sequence, DMA lifetime or storage-write guard was changed.

HPM follow-up: a wrong selector or invalid response length now returns
`-EPROTO`; exhausting the selector polling limit returns `-ETIMEDOUT`.
Both failures still latch permanently for the instance and prevent further
bus operations. The transport test runner now also runs the logical HPM
tests. Eight sanitizer-backed groups pass. Existing installed binary pins
remain unchanged.

The proxy HPM host bridge now supports Linux shared libraries through `$CC`
or `cc`. Eighteen FFI/policy tests pass here; one test requires the absent
private live ADT and skips. The default command still opens no device, and
the live image/device guards were not widened.

A Linux per-core execution check is prepared in `smp/check-linux-cpus.py`.
It refuses to start workers unless all 18 CPUs are already online and allowed
by process affinity. Each worker pins itself to a CPU, checks its executing
CPU and hashes 16 MiB against a fixed expected digest. Missing, duplicated,
failed or timed-out workers cannot pass. Five host tests pass, including one
real worker on the home server; no M5 core was tested by them.

## Power and clock findings

The exact kernel creates SMC battery/power and input devices without child DT
nodes. RTC and hwmon use DT children, but adding empty nodes is insufficient:
RTC also requires its `rtc_offset` NVMEM provider; hwmon needs sensor mappings.
Neither was invented to make probing appear successful. Incorrect system time
previously caused certificate validation failure; disabling TLS verification
is not a fix.

The SMC SRAM investigation found a concrete transfer-width mismatch. Apple's
26A428 driver uses 32-bit reads and writes, including padded partial words;
the pinned Linux helper uses 64-bit accesses for long transfers. Historical
battery probing faulted on a 64-bit read. The new [SMC patch](../smc-driver/README.md)
prepares a default-off J714s-only word-transfer mode, refuses unaligned SRAM,
corrects short-reply copying, keeps key metadata under its command mutex and
rejects failed/atomic states before staging writes. Five sanitizer-backed
host groups pass, with five regression mutations independently detected.
The exact-kernel builder now accepts the pinned SMC source and builds the
six-module set with strict export checks. Eight build tests pass. Battery
blacklists and installation pins remain unchanged; the access-width
hypothesis still needs hardware evidence.

The same pinned battery driver only partly includes macOS 27 compatibility:
its one-byte critical-status check is present, but remaining charge still
always uses the old byte order. A separate patch backports upstream's
firmware-dependent conversion for charge and energy, and contains read errors
before those paths use their output. Two sanitizer-backed groups check all
16-bit input values in both firmware modes. This does not enable the battery
driver or change its existing charging-policy writes at probe. The seven-module
candidate build passes strict export checks and nine builder tests; both
byte-order regression mutations fail their intended assertions.

The shutdown builder's two synthetic-bundle tests pass. Its temporary files
now go to Trash, including failed builds. The exact private v7 source image
remains unavailable here, so no v8 image was generated or installed.

CPU startup remains unresolved. Existing six-core-cluster indexing corrections
and timeout containment need a separately reviewed, attended hardware session.
The earlier iBoot analysis used a different Stage2 version. Matching public
Stage2 `18000.161.9` and Stage1 `20457.1.29` components have now been recovered
and checked against their Apple manifest digests. Stage2 confirms the reset
mask; Stage1's relocation destination matches the recorded boot CPU
`RVBAR_EL2`. Neither establishes a failed secondary's execution path.
Details and hashes are in [the CPU investigation](audit-2026-09-25/smp.md).
The 2026-09-27 upstream SMP refactor also fixes shared-state cache mappings
and CPU identity after deep WFI. It spans the linker, MMU and reset assembly;
copying its new `smp.c` alone would miss those dependencies. It supplies no
demonstrated T6050 reset-release fix, and the local mask/timeout guards remain
necessary. The investigation records the exact upstream commits.
Native N1 Wi-Fi and GPU acceleration remain unsupported by this work.

The loader investigation has progressed from four checked objects to a
complete offline link. The new full-link script combines pinned upstream
sources with the archived main/payload path and current guarded components.
Both C/assembly/Rust ELF files have no undefined symbols. Linked-code
inspection confirms the standalone entry, diagnostic ordering and early
T6050 NVMe refusal. Eight SMP/build-refusal tests pass. The exact private v7
payload is still absent, and no bootable replacement was packaged or installed.

The CPU kernelcache trace also now connects `AppleARMCPU::startCPU` through
the specialized enable-core function to the already inspected mask-based
PMGR path. Those wrappers add no separate entry-address write or reset
release. The CPU investigation records the dispatch addresses and the limit:
earlier platform initialization and failed-secondary execution remain unresolved.
